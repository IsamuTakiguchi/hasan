# 面談メモ整形スキル

手続種別（meta.proc_type）が管財（法人）の事件では、聴取相手は代表者・経理担当者等に
なる。発言者を明記して記録する（例「（代表者）」「（経理担当）」）。

面談中の走り書き・音声書き起こし（テキスト）を、後工程（intake）が読める
構造化された面談メモ（docx）に清書する。

## 手順

1. 元テキストを受け取る（チャット貼り付け・ファイルいずれも可。音声ファイルは
   書き起こしテキストにしてもらう）。
2. **聴取シートと同じ節構成**（hearing-sheet スキルの節1〜10）に発言内容を振り分けて
   spec.yaml を組み立てる（`cases/<事件ID>/work/menmemo_spec.yaml`）。
   - メタ情報: 面談日・場所（事務所/WEB/電話）・出席者・聴取者
   - 各節の項目は「・」の事実記載（check は使わない）
   - **「未確認・次回確認」節を必ず最後に置き**、聴取シートの標準項目のうち
     元テキストに現れなかったもの・曖昧なままのものを列挙する
3. `hasan-kit memo-docx --spec ... --output cases/<事件ID>/input/面談メモ_<日付>.docx`
   （**input/ に保存** — 原資料になる。事件フォルダが無ければ作る）
4. 作成後、利用者に (a) 内容の確認と、(b) このまま intake で case.yaml に
   取り込むかを尋ねる。取り込む場合の出所表記は「面談メモ（R7.9.1聴取）」形式。

## 整形の鉄則（原資料になるため）

- **事実の補完・推測をしない**。元テキストに無いことは書かない。
  聞き取れない・曖昧な箇所は「（不明瞭）」「（要確認）」と明示する。
- 曖昧な日付・金額は依頼者の言った粒度のまま記録する
  （「R4後半ころ」「月に2〜3万円くらい」）。勝手に精密化しない。
- 発言の要約はよいが、法的評価を混ぜない（「浪費と認められる」等と書かない。
  「パチンコに月3万円程度・2年間」という事実の形で書く）。
- 依頼者の訂正・言い直しは最終的な発言を採り、重要な変遷（当初は無いと言っていた
  借入れを後で認めた等）は「（当初は○○と述べたが訂正）」と残す。
- 免責に関わる不利な事実も**そのまま記録する**（隠さない。弁護士の判断材料）。

## 注意

- 面談メモは依頼者情報そのもの。cases/ の外に複製しない・コミットしない。
- `hasan-kit` が PATH に無い環境では `ls ~/.claude/plugins/*/*/bin/hasan-kit` 等で
  実体を探して絶対パスで使う。
