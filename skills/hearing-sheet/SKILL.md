# 聴取シート（面談準備）生成スキル

面談で聞くべき項目を網羅したチェック式シート（docx）を作る。項目構成は
**申立書類一式が要求する情報**（case.yaml スキーマ＝登録済み書式）に対応させ、
面談後はこのシートの記入結果がそのまま intake の原資料になる。

## 手順

0. **手続種別の確認**: `meta.proc_type`（無ければ利用者に選択してもらう —
   同時廃止／管財（自然人）／管財（法人））。節構成が種別で変わる:
   - **同時廃止**: 下記の節1〜10
   - **管財（自然人）**: 節1〜10 ＋「管財手続の説明・準備」節
     （予納金・管財費用の準備／自由財産拡張の希望（99万円までの現金・生活に必要な財産）／
     郵便物の転送があることの説明／管財人面接の日程）
   - **管財（法人）**: 法人用構成に差し替え —
     法人概要（商号・本店・設立・資本金・株主）／役員（就任経緯・報酬・借入）／
     従業員（人数・未払賃金・解雇の状況・社会保険）／主要取引先と売掛・買掛／
     借入と担保権（金融機関・保証協会・担保物件）／リース物件／税公課の滞納／
     帳簿類・重要書類の所在／事業所・在庫・什器の現状／破綻の経緯（時系列）／
     代表者個人の破産申立ての有無
1. **モード判定**:
   - `cases/<事件ID>/case.yaml` が**無い** → **初回シート**（全項目版）
   - ある → **差分シート**: case.yaml で出所付きで埋まっている項目は
     「■ 確認済み（要点を併記）」に落とし、**未確認・矛盾（open_questions /
     questions.md）を先頭の節に集める**
2. spec.yaml（構成は `hasan-kit memo-docx` のdocstring参照）を
   `cases/<事件ID>/work/hearing_spec.yaml`（事件未登録ならカレント）に組み立てる。
3. `hasan-kit memo-docx --spec ... --output cases/<事件ID>/work/聴取シート_<日付>.docx`
4. `hasan-kit preview` でPDF化して体裁を目視（可能な環境のみ）。

## 初回シートの節構成（この順で）

1. **基本情報** — 氏名・ふりがな・生年月日・住所（住民票どおりか）・本籍・連絡先・
   旧姓借入の有無・生活保護受給の有無
2. **経歴**（申立ての7年前〜現在） — 勤め先／自営／法人代表の別・期間・月収・退職金の有無
3. **家族・住居** — 婚姻歴、同居家族（氏名・年齢・職業・収入）、住居の形態・家賃
4. **借入れの全体像** — 借入先ごとに: 名称・いつから・使途・現在残高・保証人・担保。
   「他に借りているところは本当にないか」（信用情報の取得同意も確認）
5. **財産**（財産目録B1109の15区分に対応） — 現金5万円以上／預貯金（全口座）／保険／
   積立金／敷金／貸付金／退職金見込／不動産／自動車／10万円以上の動産／その他財産／
   2年以内に処分した財産（20万円以上）／支払不能後に返済した相手／近く入る予定のお金／過払金
6. **家計**（B1111の費目で直近2か月） — 収入（給与・年金・手当・援助）と
   支出（住居費・食費・光熱費・通信費・保険料・教育費・債務返済実額 等）
7. **破産に至った事情**（時系列） — 借入れが増えた理由・返せなくなったきっかけ・
   支払不能になった時期
8. **免責に関わる事項**（正直に話してもらう前置きを添える） — ギャンブル・飲食・
   投資・高額購入の有無、特定の人にだけ返した弁済、過去7年内の破産・再生
9. **（個人事業者のみ）事業関係**（B1112対応） — 屋号・事業内容・期間・直近3年の
   売上/経費/従業員・事業用資産・売掛金・税金滞納
10. **お持ちいただく資料**（チェックリスト） — 調査票・通帳（全口座、記帳済み）・
    保険証券・車検証・給与明細・源泉徴収票・家計の領収書・（事業者）確定申告書 等

各項目は `check: true, blank: true`（□＋記入下線）を基本にし、自由記述の想定される
項目（事情の時系列等）は `lines: 3〜5`。

## 差分シート（2回目以降）の規則

- 節1に「**前回からの確認事項**」を置き、questions.md / open_questions の各項目を
  理由付きで列挙（例: 「□ 戊田銀行の保証人の有無 — 債権調査票に記載がないため」）
- 確認済み項目は `done: true` で「■ 職歴: 乙山ストア代表 H22.6〜R7.2（確認済み）」の
  ように要点併記で残す（面談中に矛盾に気づけるように）
- 資料間の矛盾は**両方の値を明記**して確認を求める形にする

## 注意

- 聴取シートは**事務所内資料**（footer にその旨を入れる。裁判所提出物ではない）
- 依頼者に見せる資料になり得るため、断定的・非難的な表現を避ける
  （例:「浪費の有無」→「趣味や娯楽に使った金額」）
- `hasan-kit` が PATH に無い環境では、**この SKILL.md の2階層上**の `scripts/hasan-kit` を絶対パスで呼ぶ（SKILL.md はプラグインルート直下の skills/ 配下にある）。
