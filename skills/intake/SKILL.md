# 破産事件 intake（原資料 → 事件モデル）スキル

`cases/<事件ID>/input/` の原資料を解析し、**唯一の真実**となる `case.yaml` を作る。
以後のすべての書式生成は case.yaml だけを読む。原資料の読取りはこの工程で1回だけ行う。

**事件データの置き場所**: `cases/` は**現在の作業フォルダ**（利用者の事件管理ディレクトリ）
に作る。プラグインのインストールディレクトリ（`hasan-kit root` の場所）には絶対に
置かない — プラグイン更新で消える上、依頼者情報を配布物に混ぜることになる。
作業フォルダの `cases/` は必ず git 管理外にする（.gitignore に `cases/`）。

## 手順

1. **事件フォルダの確認**: `cases/<事件ID>/` に `input/ work/ output/` が無ければ作る
   （`cases/README.md` の規約参照）。事件IDは `<年>-<連番>-<識別名>`。
2. **資料の棚卸し**: input/ を走査し、資料の種類を分類してから読む。
   - PDF → pdf スキル（スキャンなら OCR）。通帳PDFは nyushukkin-bunseki に回す
   - Word（調査票・法人用報告書・面談メモ）→ docx スキル
   - Excel（債権者リスト等）→ xlsx スキル
   - 音声 → 書き起こしテキストがあればそれを読む（無ければ利用者に書き起こしを依頼）
3. **case.yaml の作成・更新**: `schema/case.schema.yaml` に従って記入する。
   記入例は `schema/examples/case.sample.yaml`（架空事例）。
4. **検証**: `hasan-kit validate-case cases/<事件ID>/case.yaml` を通す。
5. **questions.md の出力**（後述の書式）。
6. 利用者へ報告: 読み取った資料一覧・埋まった区分・確認事項の件数。

## 記入の鉄則

- **出所タグ付けの義務**: 記入した値には必ず `sources` に出所を付ける
  （例 `"creditors[2].balance": "債権調査票（庚山カード）p1"`）。ページ番号まで書く。
  出所を付けられない値は記入しない。
- **事実がない欄は書かない**。空欄は「不明」の意思表示であり、書式生成時に
  空欄のまま残されて確認事項に回る。0 と不明を混同しない（不明は null）。
- **資料間の矛盾はその場で潰さない**: どちらかを勝手に採用せず、両方の値と出所を
  `open_questions` に記録して弁護士の判断を仰ぐ
  （例: 受任通知日が受任通知控えと法人用報告書で異なる、家族の年齢が資料により食い違う）。
- **日付は原資料の粒度のまま**: 「R4後半ころ」のような曖昧値も文字列でそのまま書く。
  勝手に精密化しない。短縮元号（H22.6 / R7.2）を標準とする。
- **金額は円単位の整数**（カンマなし）。万円表記の資料は円に換算し、換算した旨を
  sources に注記する。
- **家計の費目は家計収支表書式（B1111）の正規名で記録する**
  （`$(hasan-kit courts)/osaka/forms/kakei-shushi/<版>/fillmap.yaml` の item_rows 参照。
  例: 家賃→住居費、水道光熱費→電気代/ガス代/水道代に分けて記録。分けられない
  資料しかない場合はまとめず questions.md で内訳を確認する）。
- 法人代表者の事件で**法人用報告書**がある場合: 法人の破綻経緯は `timeline` に
  個人視点（連帯保証債務との関係を明示）で書き直して取り込む。
- 調査票のチェック項目（借金の理由等）は、該当する `timeline` / `menseki` /
  `creditors[].use` に反映する。

## 各区分の読み方

| case.yaml 区分 | 主な原資料 |
|---|---|
| meta | 委任契約書・受任通知控え・住民票 |
| career | 調査票・面談メモ・法人登記事項証明書・給与明細 |
| family | 調査票・住民票・面談メモ |
| creditors | 債権調査票（債権者からの届出）・受任通知の宛先リスト・信用情報 |
| assets | 通帳・保険証券・解約返戻金証明書・車検証・査定書・不動産登記 |
| household | 家計簿メモ・領収書・給与明細・通帳 |
| timeline / menseki | 面談メモ・法人用報告書・聴取書 |
| business | 確定申告書・帳簿・面談メモ（**個人事業者の事件では必須**。屋号・事業期間・過去3年の売上/経費/従業員・事業用資産・売掛金・公租公課滞納） |
| bank_analysis | 通帳（nyushukkin-bunseki が記入する。手で埋めない） |

`meta.shiharai_funo`（支払不能時期）は面談メモ・最終弁済日から弁護士が判断する事項
なので、資料に明示がなければ open_questions に回す。

## questions.md の書式

```markdown
# 確認事項 — <事件ID>（最終更新: <日付>）

## 要確認（書式生成に影響）
1. **戊田銀行の保証人の有無** （creditors[0].guarantor）
   - 理由: 債権調査票に他の保証人欄の記載がない（未確認）
   - 影響する書類: 債権者一覧表・報告書
2. ...

## 資料間の矛盾
1. **受任通知日** — 受任通知控えは R7.3.10、法人用報告書は R7.3.12
   - どちらを採用するか確認。現在 case.yaml は受任通知控えの値を採用

## 不足資料
- 直近2か月分の水道光熱費の領収書（家計収支表に必要）
```

回答を得たら case.yaml に反映し、該当する `open_questions[].answered` に回答を記録
してから項目を消す（questions.md も更新する）。

## 依頼者情報の取扱い

原資料・case.yaml・中間物は `cases/<事件ID>/` の外に複製しない（一時作業は
scratchpad 可。リポジトリ内の他の場所は不可）。コミット対象にもしない（CLAUDE.md 鉄則1）。
