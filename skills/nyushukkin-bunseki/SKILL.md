# 入出金分析スキル

報告書第３（免責不許可事由）と家計収支表の裏付けになる工程。検出は機械的な「候補」で
あり、採否と依頼者への聴取は弁護士が判断する。

## 手順

1. **通帳の正規化**: `cases/<事件ID>/input/` の通帳PDF・画像を pdf スキルで読み取り
   （スキャンならOCR）、`cases/<事件ID>/work/bank.csv` に起こす。
   列: `date,account,description,in,out`
   - date は短縮元号（R7.1.15）。account は「銀行名 支店名」。
   - in/out は円の整数（片方は0）。摘要（description）は**通帳の表記のまま**
     （半角カナもそのまま。勝手に清書しない — キーワード検出の対象のため）。
   - 読み取れない行・不鮮明な行は飛ばさず `description` に「（判読不能）」と書いて残す。
2. **機械検出**:
   ```
   hasan-kit bank-analyze \
     --csv cases/<事件ID>/work/bank.csv \
     --case cases/<事件ID>/case.yaml \
     -o cases/<事件ID>/work/bank_analysis.yaml
   ```
   閾値は既定20万円（`--threshold` で変更可。事件の規模に応じて判断）。
3. **検出結果の吟味**: 候補を1件ずつ見て、
   - 明らかな誤検出（家賃・保険料等の定常支出）は除外
   - 残す候補を case.yaml の `bank_analysis` にマージ
   - 聴取が必要なもの（使途不明金・資産処分の原資等）を `open_questions` と
     questions.md に追加
4. **免責関係への反映**:
   - ギャンブル疑いが実際の聴取で裏付けられたら `menseki.rouhi.ギャンブル` を更新
   - 受任通知後弁済・偏頗弁済疑いは `menseki.henpa` の有無判断の材料にする
     （報告書第３の３【有無】に直結）
   - 支払不能時期前後の資産処分は `menseki.asset_disposal` へ
5. `hasan-kit validate-case` を通す（受任通知後弁済フラグと日付の整合が検査される）。

## 分析の観点（検出規則の背景）

- **偏頗弁済**（破産法252条1項3号）: 支払不能を知りながら特定債権者にだけ弁済する
  行為。受任通知後の弁済は特に問題になるため必ず拾う。親族・知人への送金も
  債権者一覧に載らない偏頗の可能性があるので、摘要に個人名がある出金は聴取対象。
- **使途不明金**: 管財人が必ず確認する。大口の現金引出は使途を聴取して
  報告書・家計の記載と整合させる。
- **資産処分**: 申立直前の解約返戻金・売却代金の入金は、その使途まで追う
  （財産隠匿・偏頗弁済の原資になっていないか）。
- 対象期間は原則、申立前2年分（裁判所・管財人の運用に応じて拡張）。
