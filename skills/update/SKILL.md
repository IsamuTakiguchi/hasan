# 事件更新（差分検知 → 質問 → 反映）オーケストレータ

**目的**: 利用者が細かい指示を書かなくても、Claude 側が「何が増えた・変わったか」を
見つけ、必要な確認質問をして、事件モデルと書類を最新化する。

## 出力形式の鉄則（必ず守る）

- 書類の更新は各スキル（intake / generate / hearing-sheet 等）の手順に従い、
  **必ず hasan-kit 経由**で行う（Word/Excel/Markdown の自作は禁止）。
- hasan-kit の実体は**この SKILL.md の2階層上**の `scripts/hasan-kit`。
- 失敗したら自作せず停止し、エラーと `hasan-kit doctor` の結果を報告する。

## 手順

1. **差分検知**: `hasan-kit scan --dir <事件フォルダ>` を実行する
   （終了コード 2=差分あり／0=変更なし。初回は全ファイルが「新規」扱い）。
   - 変更なし → その旨を報告し、questions.md の未回答事項があれば
     「この点の確認が残っています」と提示して終了。
2. **差分の分類と読み取り**（種類ごとに対応が違う）:
   - **受領資料の新規・変更ファイル** → intake の手順で読み取り、case.yaml に
     追記・更新する（sources 必須。既存値と食い違う場合は上書きせず
     open_questions に両方の値と出所を記録）。通帳・取引明細は nyushukkin-bunseki へ。
   - **記入済みの聴取シート**（work/ の聴取シート docx が変更された、または
     受領資料/ にスキャン・記入版が置かれた）→ docx／pdf スキルで読み取り、
     **記入・チェックされた項目を抽出**して case.yaml に反映する
     （出所は「聴取シート（記入版・R7.9.1）」形式。空欄のままの項目は
     「未確認のまま」として扱い、勝手に埋めない）。
   - **case.yaml が手で編集されていた** → `hasan-kit validate-case` を通し、
     エラーがあれば内容を利用者に確認する。
   - **申立書類/ 内のファイルが手で修正されていた** → 上書き再生成すると
     手修正が消えるため、**必ず利用者に確認**してから扱いを決める。
3. **確認質問（Claude 側から能動的に）**: 反映の前に、次に該当があれば
   AskUserQuestion（使えない環境では番号付きの質問リスト）で確認する:
   - 資料間・聴取シートと資料の**矛盾**（両方の値と出所を示して選んでもらう）
   - 読み取りが**曖昧**な記載（手書き・不鮮明スキャン・「10万くらい」等）
   - 新資料が**どの事件データに当たるか不明**なもの
   - 申立書類の再生成範囲（全部作り直すか、影響のある書類だけか）
   質問は一度にまとめて（5件以内目安）。確認できない項目は questions.md へ。
4. **反映と再生成**:
   - case.yaml 更新 → `hasan-kit validate-case` を通す。
   - **影響のある申立書類だけ**を該当スキルの手順で再生成する（例: 債権者の
     追加なら債権者一覧表＋申立書＋資産及び負債一覧表。家計だけなら家計収支表）。
     どれに影響するか判断に迷えば generate で一式再生成。
   - `hasan-kit crosscheck` 全OK を確認（形式監査含む）。
   - questions.md を更新（解消した項目を消し、新規確認事項を追加）。
   - **聴取シートの差分シート**を hearing-sheet の手順で作り直す
     （残っている未確認事項＋新たな矛盾を〔出典〕付きで反映）。
5. **状態の記録**: すべて終わったら `hasan-kit scan --dir <事件フォルダ> --write`
   で処理済み状態を保存する（次回の差分検知の基準になる）。
6. **報告**: 「検知した差分 → 反映した内容 → 再生成した書類 → 残る確認事項
   （questions.md）→ 次にお願いしたいこと（不足資料等）」の順で簡潔に。

## 注意

- intake / generate / hearing-sheet を呼ぶときも、それぞれの SKILL.md の
  手順・鉄則に従う（このスキルは順序と差分判断だけを受け持つ）。
- 「前回の状態記録なし（初回）」で、既に case.yaml や申立書類が存在する場合は、
  過去に処理済みの可能性が高い。ファイルの日付と case.yaml の内容を見て、
  未反映と思われるものだけ質問のうえ取り込む（全部を二重取り込みしない）。
- 利用者が明示的に別の作業を指示した場合（「報告書だけ作って」等）は
  そのスキルを優先し、終わりに scan --write だけ実行しておく。
