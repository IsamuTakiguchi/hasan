# 裁判所書式の登録・更新 運用手順（人間向け）

裁判所配布の書式（Word/Excel）は非公開で、随時改訂される。このリポジトリでは書式を
**版として保存**し、記入位置を **fillmap.yaml（アンカー定義）** で管理することで、
改訂時の追従を「新ファイルを置いて1コマンド＋差分確認」まで軽くしている。

## 新しい書式・改訂版を受け取ったら

Claude に次のように頼むだけでよい（hasan-register-form スキルが動く）:

> 「堺支部の債権者一覧表の新しい書式を受け取った。`~/Downloads/一覧表.xlsx` を登録して」
> 「報告書の書式が ver4.1 に改訂された。このファイルで更新して」

Claude がやること（概要）:

1. `courts/<裁判所>/forms/<書式>/v<版>/template.xxx` として保存（原本は編集しない）
2. 機械解析（inspect_docx.py / inspect_xlsx.py）でアンカー一覧をダンプ
3. 改訂の場合: `diff_fillmap.py` が旧版の記入位置定義を新版に**自動再束縛**
   - 裁判所の再配布ファイルは内部ID（paraId）が総入替えになるが、文言・構造パス・
     文書内位置の多層照合で吸収する（報告書 v4.0 の模擬改訂テストで229アンカー全件
     自動再束縛を確認済み）
   - 吸収できなかった欄（文言変更・欄の増減）だけが BROKEN として報告され、
     Claude が新書式を読んで手直しする
4. 差分レポート `diff-from-v<旧>.md` を生成（何が変わったかの記録）
5. 架空事例（乙山ストア事例）でスモークフィル → PDF目視 → 合格したら
   `registry.yaml` の `current:` を新版に切替え

## 確認すべきポイント（弁護士）

- 差分レポートの「新設候補」— 新しい記入欄が増えていないか
- スモークフィルのPDF — 記入位置・チェック位置が正しいか
- 改訂で記載ルール（文字数制限・費目名など）が変わっていないか

## ディレクトリの読み方

```
courts/osaka/forms/houkokusho/
├── registry.yaml        # current: "v4.0" ← 生成に使われる版
├── v4.0/
│   ├── template.docx    # 裁判所配布の白紙原本（編集禁止）
│   ├── fillmap.yaml     # 記入位置のアンカー定義（生成ロジックはこれだけを見る）
│   ├── structure.md     # 書式の構成・注意点（人間向け）
│   ├── anchors.txt      # 機械解析の生ダンプ（登録時の証跡）
│   └── examples/values.sample.yaml  # 架空事例の記入値（回帰テスト用）
└── v4.1/                # 改訂が来たらここに追加（旧版は消さない）
    └── ... + diff-from-v4.0.md
```

## してはいけないこと

- template.* の直接編集（記入は必ずコピーに対して）
- 旧版の削除（過去事件の再現に必要）
- このリポジトリの public 化・書式ファイルの外部送信（裁判所の非公開資料）
