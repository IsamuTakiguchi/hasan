# 個人破産申立て「報告書」作成スキル

大阪地裁（堺支部）様式の「報告書」（自然人用）を対象とする。
書式は①冒頭の署名欄、②第１（経歴等＝職歴表・婚姻歴・家族・相続・住居）、
③第２（破産申立てに至った事情）、④第３（免責不許可事由）で構成される。
書式の構造・記入欄の定義は `courts/osaka/forms/houkokusho/<版>/` の
`structure.md` と `fillmap.yaml` を参照。

## 前提と基本方針

- **入力は事件モデル** `cases/<事件ID>/case.yaml`（なければ hasan-intake で作成する）。
  生成器が原資料を直接読むことは禁止（CLAUDE.md 鉄則4）。
- **テンプレートと版**: `courts/osaka/forms/houkokusho/registry.yaml` の
  `current:` が現行版。利用者が事件フォルダ内の報告書（.docx）を指定したときは、
  それが登録済みテンプレートと同版か確認して使う（違う書式なら hasan-register-form
  での登録を案内する）。
- **元ファイルは絶対に上書きしない**。出力は `cases/<事件ID>/output/報告書_<姓>_記入済み.docx`。
- **根拠のない記載はしない**。case.yaml の `sources` に出所のある事実だけを記入し、
  裏付けのない欄は空欄のまま残す。推測で補った箇所は最後に必ず確認事項として報告する。
- 記入は**既存docxのXML編集**による（レイアウト完全保持）。実作業は
  `scripts/build/fill_docx.py` が fillmap 駆動で行うので、このスキルの仕事は
  **case.yaml から values.yaml（記入値）を下記の体裁ルールに従って組み立てること**。

## 手順

1. `python3 scripts/casekit/validate_case.py cases/<事件ID>/case.yaml` を通す。
2. case.yaml を読み、下記の体裁ルールに従って `cases/<事件ID>/work/houkokusho_values.yaml`
   を作成する。書式は `courts/osaka/forms/houkokusho/v4.0/examples/values.sample.yaml`
   （架空事例の完全な見本）に倣う。field_id は fillmap.yaml に定義されたものだけを使う。
3. 記入を実行する:
   ```
   python3 scripts/build/fill_docx.py \
     --template courts/osaka/forms/houkokusho/<版>/template.docx \
     --fillmap  courts/osaka/forms/houkokusho/<版>/fillmap.yaml \
     --values   cases/<事件ID>/work/houkokusho_values.yaml \
     --output   cases/<事件ID>/output/報告書_<姓>_記入済み.docx
   ```
   validate が通ること（アンカー解決失敗の警告が出たら fillmap か書式版の不一致を疑う）。
4. **必ずPDF化して目視検証する**（後述）。

## values.yaml 組み立ての体裁ルール（このスキルの核心）

### 1. 冒頭の署名欄

- `sign_dairinin`: 代理人は原則筆頭1名。氏名には必ず肩書「弁護士」を付け、
  「弁護士　乙　川　一　郎」のように1字ずつ全角スペースで割り付ける。
  連名は利用者から明示の指示があったときだけ（fillmap 外の編集になるため、その際は
  docx スキルで代理人行の `<w:p>` を複製し、2行目のラベルは全角スペース6字で字下げ）。
- `sign_moushitatenin`: 「甲　野　太　郎」形式。
- `hokoku_date`: 提出日が確定しているときだけ正式表記（令和７年９月１日）で入れる。
  未定なら値を入れない（空欄のまま提出直前に手書き・後日記入）。

### 2. チェックボックス

- 値は fillmap の選択肢キー（例 `勤め` `法人代表者` `有` `無`）。複数選択可の欄は
  リストで渡す（例 `shakkin_riyu: [事業経営破綻, 債務保証]`）。
- 根拠資料で確認できない選択肢はチェックしない（値を渡さない）。
- 【□有　□無】欄は、資料から有無が判断できるときだけ `有` / `無` を入れる。

### 3. 職歴表（shokureki1〜8）

- **1組目が現職**（期間endは「現　在」印字済みなので値不要）、以降は新しい順。
- **記入するのは現在から申立ての7年前までをカバーする範囲だけ**。7年前をまたいで
  続く在職は実際の開始年月から書いてよい（例 H22.6～R7.2）。
- **日付は短縮元号表記**（半角）: `R7.2～` `H22.6～`。正式表記はセル幅
  （約14全角文字/10pt）を超えて行高が変わるため使わない。startは「～」まで含める。
- **1セル1行厳守**。就業先は短縮し、地位は括弧書きで併記（例 `株式会社乙山ストア（代表取締役）`）。
- 月収は半角数字カンマ区切り（例 `200,000`）。
- `shokurekiN_taishokukin: 有り` は退職金の存在が資料で確認できたときだけ。

### 4. 第２の５「具体的事情」（gutaiteki_jijo）

- 値は `[{date: ..., text: ...}]` のリスト。日付は短縮表記
  （`H22.6` `R4後半ころ` `R6.11ころ`）。行が足りなければ自動で複製される。
- 内容は時系列で: 開業・就職 → 経営悪化／収入減の原因（競合出店・物価高等の外部
  要因を具体的に）→ 返済困難化（リスケ等）→ 支払不能・営業停止・受任。
- 申立人が法人代表者の場合は、法人の破綻と本人の債務（連帯保証等）のつながりを明示する。
  法人用報告書（破産原因の経緯欄）があれば個人視点に書き直して使う。
- 句読点は書式に合わせ「，」「。」を使う。

### 5. 下線長文欄（sairyo_jijo_text / sonota_menseki_text / hanron_text）

- 全文を1つの値として渡す（fill_docx.py が空欄段落を統合して自然に折り返させる。
  行ごとに手で切ってはならない）。

### 6. 第３の７「裁量免責され得る事情」の書き方

`sairyo_umu: 有` とし、`sairyo_jijo_text` に次の3点を簡潔に（3〜6文程度）:
1. 負債の原因が浪費・射幸行為ではなく、外部要因による事業破綻・失職等であること。
2. 第３の１で「有」にした支出があれば、その必要性・相当性
   （例: タイヤは通勤のために必要な支出、家電は生活に必要な範囲の支出）。
3. 廃業時の誠実な対応（事業譲渡による取引先・従業員への配慮等）と破産手続への協力姿勢。

## 検証（必須）

1. fill_docx.py の validate が通ること（--original 検証込み）。
2. `python3 scripts/verify/render_preview.py cases/<事件ID>/output/報告書_～.docx` で
   PDF・ページ画像化し、画像を Read して目視確認する。チェックポイント:
   - 職歴表の各セルが**1行**に収まっているか（折返しで行高が変わっていないか）。
   - 第２の５の内容列の折返しが揃っているか（全行にぶら下げインデントが効いているか）。
   - 下線欄の文章が自然に折り返しているか（途中で段落が切れていないか）。
   - チェック（☑）が意図した選択肢に付いているか。
3. 崩れていたら、日付の短縮・就業先名の短縮で values.yaml を直して再実行する。
4. この環境のPDF描画は代替フォントのため、Word実機とは折返し位置が多少ずれる。
   セル内の折返しはWordでも起きる可能性が高いので必ず直す。

## 仕上げの報告

作業後は次を箇条書きで利用者に報告する:
- 記入した項目の一覧
- 根拠資料がなく**空欄のまま残した項目**（例: 約定返済月額、提出日）
- 推測を含む記載や、資料間の**矛盾**（例: 受任通知日が法人用報告書と異なる、
  家族の年齢・職業が資料により食い違う）→ 利用者の確認を求める
  （case.yaml の `open_questions` にも追記して questions.md に反映する）

## 記入例（架空事例）

完全な見本は `courts/osaka/forms/houkokusho/v4.0/examples/values.sample.yaml` を
参照（乙山ストア事例）。要点の抜粋:

- 職歴表1組目（現職）: `shokureki1_start: R7.2～`、`shokureki1_shubetsu: 勤め`、
  `shokureki1_shugyosaki: 株式会社丁原食品（配送員）`、`shokureki1_gekkyu: "200,000"`
- 職歴表2組目（旧職）: `shokureki2_start: H22.6～`、`shokureki2_end: R7.2`、
  `shokureki2_shubetsu: 法人代表者`、`shokureki2_shugyosaki: 株式会社乙山ストア（代表取締役）`
- 受任通知発送日 R7.3.10 → `junin_tsuchi_date: ["７", "３", "１０"]`（全角数字のリスト）
- 支払不能 R7.1・約定返済額不明 → `shiharai_funo: ["７", "１", ""]`（不明スロットは空文字）
